# b1: fire incident

Zone: B (building)
Layers involved: Twin, Guardian, Brain

## Trigger

One trigger starts the scenario. Either of these does the same thing:

* From the page: open the Scenario Control page of the Twin (port 8080) and click the card "Fire incident".
* From the command line, at the root of the repository: `python scenarios/b1.py` (it runs `python src/twin.py run b1` in the `twin/` folder).

Each run writes one log file in `logs/`, named `b1-<date>-<time>.log`. On the page, the button "Reset all" returns every sensor to normal.

## What the Twin does

* +5 s: the building `us-b-bldg-01` starts to burn, smoke and temperature rise every tick.
* +5 s: WARNING, smoke 20 ppm and 34 C.
* +20 s: CRITICAL, smoke 80 ppm and 70 C, emergency status on.
* The fire does not stop by itself. It goes out only when the alarm is `on` and units are `dispatched`.
* +45 s: the fire is out, the sensors return to normal and the alert clears.

## What the other layers should do

The Guardian marks the smoke and the temperature as TRUSTED, because both rise together. The Brain then writes `alarmState=on` on `us-b-alarm-01` and `status=dispatched` on `us-b-disp-01`. In the timed run the Twin plays this answer at +20 s.

## Pass criteria

* Log has ALERT RAISED and ALERT ESCALATED for FIRE.
* Log has COMMAND lines for the alarm and the dispatch, then the EFFECT line "fire extinguished by dispatched units".
* Log has ALERT CLEARED for FIRE and the emergency status returns to none.

# g2: sensor faults

Zone: A (traffic)
Layers involved: Twin, Guardian

## Trigger

One trigger starts the scenario. Either of these does the same thing:

* From the page: open the Scenario Control page of the Twin (port 8080) and click the card "Sensor faults".
* From the command line, at the root of the repository: `python scenarios/g2.py` (it runs `python src/twin.py run g2` in the `twin/` folder).

Each run writes one log file in `logs/`, named `g2-<date>-<time>.log`. On the page, the button "Reset all" returns every sensor to normal.

## What the Twin does

* +5 s: `us-a-traf-03` starts to repeat the same values (stuck) and `us-a-traf-02` stops publishing (dead).
* +15 s: the operations centre raises a COMM_LOSS alert for `us-a-traf-02`, which is not reporting.

## What the other layers should do

The Guardian flags the stuck sensor and the silent one. The Brain does not act on either.

## Pass criteria

* Log has MODE stuck and MODE dead lines, and ALERT RAISED COMM_LOSS for `us-a-traf-02`.
* Guardian verdicts for `us-a-traf-03` and `us-a-traf-02` are not TRUSTED.
* No COMMAND line in the log.
